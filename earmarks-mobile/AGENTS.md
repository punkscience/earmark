# AGENTS.md

Universal context for any AI coding agent (Codex, Cursor, Copilot, Gemini, Claude, etc.) operating in the `earmarks-mobile/` subproject. Read the repo-root `AGENTS.md` first — it covers the monorepo layout and the protocol invariants shared with the CLI.

## Project Overview

**earmarks-mobile** is a minimal Android app (Kotlin + Jetpack Compose) that reads a user's *derpy* earmark list from Nostr, downloads their earmarked audio files from Blossom servers, decrypts them, caches them locally, and plays them in a shuffled playlist. Audio persists in the background and the app is Android Auto compatible.

Full protocol spec: `../docs/PROTOCOL.md`

## Build Commands

Run from `earmarks-mobile/` — the Gradle build is rooted here, not at the repo root.

```bash
./gradlew assembleDebug        # build debug APK
./gradlew assembleRelease      # build release APK
./gradlew installDebug         # build + install on connected device
./gradlew testDebugUnitTest    # JVM unit tests (crypto conformance) — runs in CI
./gradlew lint                 # lint
```

> The `gradle-wrapper.jar` must exist at `gradle/wrapper/gradle-wrapper.jar`. Generate it by running `gradle wrapper --gradle-version 8.7` once after installing Android Studio (which bundles Gradle).

## Channels

A channel is a room of Nostr identities sharing earmarks. The full contract is the Channels section of `docs/PROTOCOL.md`; what matters here:

- **The transport is NIP-59 gift wrap.** No relay knows a channel exists. `GiftWrap.kt` must stay byte-compatible with `earmark-core/giftwrap.go`.
- **Identity comes from the seal, never the rumor.** A rumor is unsigned; its `pubkey` field is attacker-controlled and is rejected on mismatch.
- **The phone is a full peer minus new-file ingest.** It can browse, play, Keep and repost. Encrypting a fresh audio file from device storage stays CLI-only.
- **Keep uses BUD-04 `/mirror`**, so the destination servers fetch the blobs themselves and no audio passes through the phone. That is the whole reason it is viable on mobile.
- **There is no backfill, and the UI must keep saying so.** A newly joined channel is empty and that is correct, not a fault. `ChannelBar` and the join confirmation both state it.
- Channel state lives in a second self-encrypted kind-30001 event, `d = "earmark-channels"`, so it syncs across devices with the key.

### The crypto is hand-written, so it is pinned to Go

`Nip44.kt`, `Schnorr.kt` and `GiftWrap.kt` are hand-written ports. Nothing stops them drifting from the Go implementation except tests, and **round-trip tests cannot catch a bug that is symmetric within this codebase**. So:

- `app/src/test/.../Nip44Test.kt` asserts conversation keys, pubkey derivation and three ciphertexts produced by `go-nostr`.
- `app/src/test/.../GiftWrapTest.kt` unwraps `app/src/test/resources/giftwrap_fixture.json`, generated by `earmark-core`'s `TestCrossClientGiftWrapFixture` and read by the Go suite too.

Regenerate the fixture with `EARMARK_REGENERATE_FIXTURE=1 go test -run TestCrossClientGiftWrapFixture` from `earmark-core`. Needing to is a protocol change; update `docs/PROTOCOL.md` and re-verify both sides.

These are JVM unit tests, not instrumented ones — the crypto deliberately uses `java.util.Base64` rather than `android.util.Base64` so it runs without a device. `org.json` is stubbed out of Android unit tests, hence the `org.json:json` test dependency.

## Key Design Decisions

**NIP-44 — manual implementation (not rust-nostr)**
The rust-nostr Android SDK (`org.rust-nostr:nostr-sdk`) doesn't yet expose NIP-44 decrypt in its Kotlin bindings. Instead, `Nip44.kt` implements the full NIP-44 v2 algorithm directly using Bouncy Castle's lightweight API (no JCE provider registration needed):
- secp256k1 ECDH via `ECDHBasicAgreement`
- HKDF-SHA256 via `HKDFBytesGenerator`
- ChaCha20 decrypt via `ChaCha7539Engine` (IETF variant, 96-bit nonce)
- MAC verification via `javax.crypto.Mac` HMAC-SHA256

**Self-encryption**: derpy encrypts the earmark list to the user's own public key. The shared secret is `privkey^2 * G` on secp256k1.

**Nostr relay access**: Raw OkHttp WebSocket, no Nostr library. Sends NIP-01 REQ/EVENT/EOSE JSON manually. Queries all 4 default relays in parallel, takes the event with the highest `created_at`.

**Cache expiry**: On every launch, fetches the fresh earmark list and deletes `cacheDir/earmarks/earmark_<ts>.*` for any `ts` values not present in the new list.

**Background audio + Android Auto**: `EarmarksMediaService` (a `MediaLibraryService`) runs as a foreground service. The UI connects to it via `MediaController` so the same player instance is shared with Android Auto.

## Crypto Constants (from spec)

| Item | Value |
|------|-------|
| Earmark event kind | `30001`, `d` tag = `"derpy-earmarks"` |
| NIP-44 conversation key salt | `"nip44-v2"` (UTF-8) |
| NIP-44 message key info | `"encryption"` (UTF-8) |
| NIP-44 message key length | 76 bytes → [0:32] chacha key, [32:44] chacha nonce, [44:76] hmac key |
| Chunk format | `[12-byte nonce][ciphertext][16-byte GCM tag]` |
| AES key | 32 bytes, base64-decoded from `blossom.key` |
| Default relays | `wss://relay.towerofsong.ca`, `wss://relay.primal.net` |
